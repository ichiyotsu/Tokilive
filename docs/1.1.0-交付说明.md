# tokilive 1.1.0 交付说明

这次把 1.0.0 的 Windows 与 Android 源码放进同一个仓库，并做到 1.1.0。没有发布 Release，也没有改动或删除 v1.0.0。

## 仓库

- `windows/`：Electron。应用 ID 仍是 `com.ichiyotsu.tokilive`。
- `android/`：Compose。`applicationId` 仍是 `com.ichiyotsu.tokilive`，`versionCode` 从 1 增到 2，`versionName` 为 1.1.0。
- 旧设置会继续从 `BiliDanmakuMD3/settings.json` 迁移。签名钥匙、Cookie、登录态不在仓库里。

## Windows

1. 设置窗口改成可折叠侧栏。宽屏展开，中等宽度只留图标，窄于 720px 时变成覆盖层，可以用标题栏按钮打开。方向键、Home、End、首字跳转和 Enter 都能用。截图见 `win-compact.png`、`win-narrow.png`。
2. 应用内更新走私人仓库 `ichiyotsu/tokilive` 的 Release API，不使用匿名下载链接。授权顺序是：系统加密保存的令牌、环境变量 `TOKILIVE_GITHUB_TOKEN`、本机 GitHub CLI。设备码需要用户自己的 OAuth client id，没有内置 PAT。令牌不回传给页面，日志会打码。下载跟随重定向时去掉 Authorization。有 sha256（资产的 `digest`，或 `SHA256SUMS`）才允许安装，不一致就删掉文件。安装前有系统确认框。NSIS 不带静默参数，安装程序可以选择目录，包括 D:。便携版在退出后按确切路径替换自身。1.0.0 没有这段代码，第一次升到 1.1.0 必须手动安装。
3. 应用外观和卡片外观分开。应用主题、强调色、背景图、不透明度和设置窗口材质在「应用外观」。种子色、卡片明暗、悬浮窗模糊和悬浮窗材质留在卡片页。导入主题不会改应用外观。
4. 窗口标题改为 `tokilive · 弹幕`、`tokilive · 互动小窗`、`tokilive · 设置`。不再使用工具窗口样式，并会把显示亲和性设为允许采集，同时保留分层透明。没有再做一个隐藏的重复窗口。OBS 浏览器源地址是 `http://127.0.0.1:端口/overlay` 和 `/mini`。本环境没有 Windows，也没有用真实的 OBS 或直播姬核对过画面。传统 BitBlt 对分层透明窗口通常仍然是黑的。
5. 「显示弹幕窗」和「显示互动小窗」分开保存。隐藏只调用 hide，不停止 WebSocket，也不销毁窗口。
6. 连接页「读取我的直播间」使用已登录 Cookie 调 `nav` 和 `xlive/web-ucenter/user/live_info`。未登录、没有直播间、接口失败都不会改房间号输入框。
7. 性能模式默认关闭。打开后只临时限制本应用的模糊、消息条数和动画，不改写已保存的外观。可以采样本进程 CPU 和内存。后台清理默认不扫描；扫描结果会去掉系统、安全软件、服务、OBS、直播姬、编码器、音频、采集、显卡、网络组件和 tokilive。只关闭勾选的 PID。先请求正常关闭，强制结束要再确认一次，并提示未保存内容会丢失。没有通配符、没有提权、没有关杀毒、没有改注册表。这些不能保证 1080p30 的直播延迟变好。Iris Xe 的说明是常见分界，不是在这台电脑上测出来的。

## Android

1. 底栏按 Material 3 Expressive 重写：未选中只有图标，选中项用弹簧展开文字，旁边是 18dp 圆角的独立操作按钮，并避开手势条。TokiNote 仓库实际是 `ichiyotsu/TokiNote`，默认分支 `main`，许可证是 GPL-3.0。这里没有复制它的源码。
2. 更新同样走私人仓库 API，令牌放在 Android Keystore。下载后核对 sha256、包名和签名。签名不一致、没有校验和、或当前安装没有可对照的正式签名时拒绝安装。通过之后用 FileProvider 打开系统安装界面，不静默安装。没有安装未知来源权限时先打开系统设置。签名钥匙没有放进仓库，这次打出来的是未签名 APK。
3. 关于页的 tokilive 字标指定内置 Google Sans Bold（`google_sans_700`），字重 700。

## 已跑过的检查

- `windows`：`node --test test`，12 项通过。
- 设置页在本机的虚拟显示里截了图，不是在用户的 Windows 电脑上。
- Android：`UpdateLogicTest` 通过；`ScreenshotTest` 四个用例通过，但 Roborazzi 这次没有把 PNG 留在磁盘上。
- `assembleRelease` 成功，产物是未签名包：`com.ichiyotsu.tokilive`，versionCode 2，versionName 1.1.0，minSdk 35。`apksigner` 报缺少 `META-INF/MANIFEST.MF`，这是未签名的结果。
- Windows 安装包和便携版由 electron-builder 25.1.8 在 Linux 上打出，文件名 `tokilive-1.1.0-setup.exe`、`tokilive-1.1.0-portable.exe`。没有在 Windows 上安装，也没有把目录选到 D:。

## 还没在真实设备上核对的事

- OBS、直播姬能否分别框住两个透明窗口，以及浏览器源里的实际画面。
- 私人仓库下载、设备码、安装包替换、便携版自替换。
- 读取自己的直播间时 B 站接口的真实返回。
- 性能模式和手动关进程对推流延迟有没有帮助。
- Android 15+ 上的安装确认、未知来源设置、签名比对。正式签名后的包才能和已安装的 1.0.0 比签名。
- 侧栏、底栏在真机上的动画和手势。

## 父机还要做的打包

1. 用原来的 Android 签名钥匙设置 `TOKILIVE_KEYSTORE`、`TOKILIVE_STORE_PASSWORD`、`TOKILIVE_KEY_ALIAS`、`TOKILIVE_KEY_PASSWORD`，再执行 `android/gradlew :app:assembleRelease`。不要把钥匙或密码提交进仓库。
2. 在 Windows 上再打一次安装包更稳妥。本环境是用 Wine 调用 NSIS。安装时可以改目录到 D:。
3. 发布 1.1.0 时请附上每个文件的 sha256，或一个 `SHA256SUMS`。没有校验和时，应用会拒绝安装。
4. 1.0.0 的用户需要先手动安装这一版。确认安装包可用之后再发 Release。
